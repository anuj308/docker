Puppet Server + Puppet Agent on AWS EC2 (Corrected Guide)

This practical demonstrates a working Puppet Server + Puppet Agent setup using two AWS EC2 Ubuntu instances.

⚠️ CRITICAL PREREQUISITES:
  1. RAM Requirement: Puppet Server 8 requires at least 4GB of RAM to generate its Certificate Authority. You must use a t3.medium (or larger) for the Server instance. Using a t2.micro or t3.small will cause the service to crash on startup.
  2. Packaging Paths: The new puppet8-release-noble.deb package uses different paths than older tutorials.
    • Config: /etc/puppet/puppet.conf
    • SSL: /var/lib/puppet/ssl
    • Code: /etc/puppet/code/
  3. Certnames: Every node must have a unique certname. Never set certname = puppet-agent on the Server. The Server must use its own FQDN.

Part 1: Launch Instances & Get IPs

  1. Launch 2 instances (Ubuntu 24.04 LTS).
    • Server Instance: Name it puppet-server, type t3.medium (4GB RAM).
    • Agent Instance: Name it puppet-agent, type t3.micro (1GB RAM).
  2. Security Group: Allow SSH (22) from your IP. Allow Custom TCP (8140) from the Agent's Security Group (or the VPC CIDR, e.g., 172.31.0.0/16). Do not expose 8140 to the whole internet.
  3. Note the Private IPs:
    • Server Private IP: _________________ (e.g., 172.31.14.71)
    • Agent Private IP: _________________ (e.g., 172.31.10.226)

Part 2: Setup Puppet Server

SSH into your Server instance.

# 1. Update and install the Puppet 8 repository
sudo apt update && sudo apt upgrade -y
wget https://apt-puppetcore.puppet.com/public/puppet8-release-noble.deb
sudo dpkg -i puppet8-release-noble.deb
sudo apt update

# 2. Install Puppet Server
sudo apt install puppetserver -y

# 3. Configure Puppet Server
# IMPORTANT: Do NOT add "certname" here. The server must use its own FQDN.
sudo nano /etc/puppet/puppet.conf

Make sure your puppet.conf looks exactly like this (delete any server = or certname = lines):

[main]
# Leave this section empty or with comments only.
# DO NOT add certname = puppet-agent here!

Save and exit (Ctrl+O, Enter, Ctrl+X).

# 4. Ensure permissions are correct
sudo chown -R puppet:puppet /var/lib/puppet

# 5. Manually generate the CA (prevents the service from crashing on startup)
sudo puppetserver ca setup

# 6. Start the Puppet Server
sudo systemctl enable puppetserver
sudo systemctl start puppetserver
sudo systemctl status puppetserver

Press q to exit the status view. Wait 30 seconds.

# 7. Verify the server is serving the correct certificate
sudo openssl s_client -connect 127.0.0.1:8140 -showcerts </dev/null 2>/dev/null | openssl x509 -noout -subject -issuer

Expected Output:

subject=CN = ip-172-31-14-71.ap-south-1.compute.internal
issuer=CN = Puppet CA: ip-172-31-14-71.ap-south-1.compute.internal

(Notice the subject is the server's FQDN, NOT puppet-agent).

Part 3: Setup Puppet Agent

Open a new terminal and SSH into your Agent instance.

# 1. Update and install the Puppet 8 repository
sudo apt update
wget https://apt-puppetcore.puppet.com/public/puppet8-release-noble.deb
sudo dpkg -i puppet8-release-noble.deb
sudo apt update

# 2. Install Puppet Agent
sudo apt install puppet-agent -y

# 3. Configure the Agent
sudo nano /etc/puppet/puppet.conf

Add these lines under [main] (replace <SERVER_PRIVATE_IP> with your actual Server IP):

[main]
server = <SERVER_PRIVATE_IP>
certname = puppet-agent

Save and exit.

# 4. Map the server IP to the name "puppet" in the hosts file
sudo nano /etc/hosts

Add this line at the bottom (replace with your Server IP):

172.31.14.71 puppet

Save and exit.

# 5. Start the agent service
sudo systemctl start puppet

# 6. Test the connection (This will generate a CSR)
sudo puppet agent --test

Expected Output:

Info: Creating a new RSA SSL key for puppet-agent
Notice: Did not receive certificate

(If you still see unable to get local issuer certificate, run sudo systemctl stop puppet && sudo rm -rf /var/lib/puppet/ssl && sudo systemctl start puppet and try again).

Part 4: Sign the Agent Certificate

Go back to your Server terminal.

# 1. List the pending certificate requests
sudo puppetserver ca list

# 2. Sign the agent's certificate
sudo puppetserver ca sign --certname puppet-agent

Expected Output: Successfully signed certificate request for puppet-agent

Part 5: Apply the Configuration

Go back to your Agent terminal.

sudo puppet agent --test

Expected Output:

Notice: Requesting catalog from 172.31.14.71:8140
Notice: Catalog compiled by ip-172-31-14-71.ap-south-1.compute.internal
Info: Caching catalog for puppet-agent
Info: Applying configuration version '...'
Notice: Applied catalog in 0.01 seconds

Part 6: Create and Apply a Manifest

On the Server:

# 1. Create the manifest directory
sudo mkdir -p /etc/puppet/code/environments/production/manifests

# 2. Create the manifest file
sudo nano /etc/puppet/code/environments/production/manifests/site.pp

Paste this exact code:

file { '/tmp/hello.txt':
  ensure  => file,
  content => "Hello from Puppet Server!\n",
}

Save and exit.

# 3. Validate the syntax
sudo puppet parser validate /etc/puppet/code/environments/production/manifests/site.pp
# (No output means it's correct)

On the Agent:

# 1. Run the agent again
sudo puppet agent --test

Expected Output: Notice: /Stage[main]/Main/File[/tmp/hello.txt]/ensure: created

# 2. Verify the file was created
cat /tmp/hello.txt

Expected Output: Hello from Puppet Server!

🚨 Troubleshooting Cheat Sheet (If things break)

If you ever get the unable to get local issuer certificate error again, it means the SSL state is corrupted. Run this "Nuclear Option" on the Agent:

sudo systemctl stop puppet
sudo rm -rf /var/lib/puppet/ssl
sudo rm -rf /var/cache/puppet/state
sudo systemctl start puppet
sudo puppet agent --test

Then go to the Server and run sudo puppetserver ca sign --certname puppet-agent again.

If the Server crashes (Job for puppetserver.service failed), check the logs:

sudo journalctl -u puppetserver -n 50 --no-pager

If it says OutOfMemory, stop your EC2 instance, change the instance type to t3.medium (4GB RAM), and start it again.
